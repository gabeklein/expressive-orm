`@expressive/postgres` runs Expressive ORM entities on Postgres and PGLite, and keeps loaded entities live as rows change. It depends on and re-exports `@expressive/sql`: import `Type`, `Query`, the field helpers and `PGConnection` or `PGLiteConnection` from here.

**Connections**

- `PGConnection.new(types, config)` - a connection string, `pg` `PoolConfig` or `Pool`. `PGLiteConnection.new(types, dataDir | pglite, options)`.
- Awaiting a connection runs `sync`: verify existing tables, create missing ones, install triggers.
- `Type.find`, `one`, `insert`, `save`, `update`, `delete` and `Type.query` execute against the database.
- `@expressive/orm` and `@expressive/sql` are dependencies; `@expressive/mvc` is a peer; `pg` and `@electric-sql/pglite` are optional peers.

**Live rows** over LISTEN/NOTIFY. `sync` installs an `expressive_notify()` trigger function and a trigger per table, which `pg_notify` the `expressive_orm` channel with `{ table, op, id, row }` - `row` omitted past 8000 bytes, and reloaded. `PGConnection` listens on a client of its pool, `PGLiteConnection` through PGLite's `listen`, from the first entity loaded until the connection is closed. Entities loaded through either follow changes made by any client. Requires Postgres 14+ (`CREATE OR REPLACE TRIGGER`); a pooler in transaction mode drops notifications.

**Datatypes** come from sql's shared vocabulary, so a column config moves between SQLite and Postgres unchanged. Postgres adds `num` `serial`, `date` `interval` with `fields` (schema only for now), and `timezone` on `timestamp` and `time`. `TimeColumn` exports postgres's subclass.

**Behaviour**

- An incrementing `id` renders `GENERATED BY DEFAULT AS IDENTITY`, so an explicit id inserts; the sequence does not advance past it.
- Schema renders `PRIMARY KEY` for any primary column (the default `id` no longer adds `UNIQUE`), `DEFAULT` for every `fallback` with `"NOW"` as `CURRENT_TIMESTAMP`, and `one()`'s `onDelete` / `onUpdate` on the foreign key. `json` is `TEXT`.
- `bool` binds JS booleans to `boolean` columns. A `timestamp` without `timezone` stores and reads UTC, as a `Date` or a string. A `time` with `timezone` reads as a `Date`.
- `RETURNING` renders through sql's generator; a query without a connection prints orm's intent dump.

**Packaging.** ESM only, built with tsdown.

Requires `@expressive/mvc` `^0.88.1`.
