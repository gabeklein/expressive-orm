# @expressive/postgres

Postgres and PGLite connections for Expressive ORM, with live rows over LISTEN/NOTIFY. Re-exports [`@expressive/sql`](https://github.com/gabeklein/expressive-orm/tree/main/packages/sql), so entities, field helpers and `Query` come from this one import. Full guide: [README](https://github.com/gabeklein/expressive-orm#readme).

```sh
npm install @expressive/postgres @expressive/mvc pg
# or embedded, in WASM
npm install @expressive/postgres @expressive/mvc @electric-sql/pglite
```

`pg` and `@electric-sql/pglite` are optional peers - install the one you connect with.

## Connections

```ts
import { PGConnection, PGLiteConnection, Type, str } from '@expressive/postgres';

class User extends Type {
  name = str();
}

const db = await PGConnection.new([User], "postgres://localhost/app");
```

- `PGConnection.new(types, config)` - `config` is a connection string, a `pg` `PoolConfig` or a `Pool`.
- `PGLiteConnection.new(types, dataDir?, options?)` - a data directory (in memory when omitted) or a `PGlite` instance, then `PGliteOptions`.

Awaiting a connection runs `sync`: it verifies existing tables against the classes, creates missing ones, and installs the live-row triggers. `sync(false)` throws for a missing table instead. A column declared `optional` and absent from the table is tolerated and reads `undefined`.

## Extras

Column configs are shared with SQLite - see [Datatypes](https://github.com/gabeklein/expressive-orm#datatypes). Postgres adds:

```ts
import { Type, date, num } from '@expressive/postgres';

class Job extends Type {
  ticket = num({ type: "serial", optional: true });
  due = date({ timezone: true });
  at = date({ type: "time", timezone: true });
}
```

- `num` `serial` - with `optional`, an insert leaves it to the sequence.
- `timezone: true` on `timestamp` and `time` renders `TIMESTAMPTZ` / `TIMETZ`. A `timestamp` without it stores and reads UTC.
- `date` `interval`, with `fields` - schema only: an interval does not yet read or write as a `Date`.

An incrementing `id` is `GENERATED BY DEFAULT AS IDENTITY`, so an explicit id inserts; the sequence does not advance past it.

## Live rows

Loaded entities follow changes made by any client.

```ts
import { PGlite } from '@electric-sql/pglite';
import { PGLiteConnection, Type, str } from '@expressive/postgres';

class Task extends Type {
  title = str();
}

const client = new PGlite();
await PGLiteConnection.new([Task], client);

const task = await Task.insert({ title: "Draft" });

task.get(({ title }) => console.log(title));

await client.query(`UPDATE task SET title = 'Final' WHERE id = $1`, [task.id]);
```

Requirements:

- Postgres 14+ (`CREATE OR REPLACE TRIGGER`).
- `sync` installs an `expressive_notify()` function and a trigger per table, each time it runs; tables created outside `sync` get theirs on the next one. Triggers `pg_notify` the `expressive_orm` channel with `{ table, op, id, row }`; `row` is dropped past 8000 bytes and the entity reloads it.
- `PGConnection` holds one pool client for `LISTEN`, from the first entity loaded until `close()`.
- A pooler in transaction mode (PgBouncer, some serverless proxies) drops notifications silently. Connect directly or in session mode.
