# @expressive/postgres

Postgres and PGlite connections for Expressive ORM, with live rows over LISTEN/NOTIFY. Re-exports `@expressive/sql`, which re-exports `@expressive/orm` - import everything from `@expressive/postgres`. Entities, `Query` and transactions are in `expressive-orm`; datatypes, `sync` and the CLI in `expressive-sql`.

```bash
npm install @expressive/postgres @expressive/mvc pg
# or embedded, in WASM
npm install @expressive/postgres @expressive/mvc @electric-sql/pglite
```

`pg` and `@electric-sql/pglite` are optional peers - install the one you connect with.

## Connect

```ts
import { PGConnection, PGLiteConnection, Type, str } from '@expressive/postgres';

class User extends Type {
  name = str();
}

const db = await PGConnection.new([User], "postgres://localhost/app");
const lite = await PGLiteConnection.new([User], "./data");
```

- `PGConnection.new(types, config)` - a connection string, a `pg` `PoolConfig` or a `Pool`.
- `PGLiteConnection.new(types, dataDir?, options?)` - a data directory (in memory when omitted) or a `PGlite` instance, then `PGliteOptions`.
- `close()` ends a pool or `PGlite` the connection created; one passed in stays open.

## Sync

Awaiting a connection runs `sync`: it verifies existing tables against the classes, creates missing ones, adds missing columns with their foreign keys and indexes, and installs the live-row triggers. `sync(false)` throws for a missing table or column instead. A missing `optional` column that cannot be added is tolerated and reads `undefined`. Type and nullability drift is reported; `sync(true, true)` alters the column, refusing while a row would not fit. `plan(force?)` and `expressive sql check|sync` work as on SQLite.

An incrementing `id` is `GENERATED BY DEFAULT AS IDENTITY` - an explicit id inserts, and the sequence does not advance past it.

## Datatypes

Column configs are shared with SQLite. This package's `sql` adds:

```ts
import { Type, date, sql } from '@expressive/postgres';

class Job extends Type {
  due = date(sql.timestamptz);                     // or date({ timezone: true })
  at = date(sql.timetz);
}
```

- `timezone: true` on `timestamp` and `time` renders `TIMESTAMPTZ` / `TIMETZ`. A `timestamp` without it stores and reads UTC.
- Datatypes are orm's portable set; `serial` and `interval` are not among them. An incrementing `id` is an identity column.

## Transactions

`db.transaction(fn)` as in `expressive-orm`. `PGConnection` runs each transaction on its own pool client, side by side; statements outside one don't wait. `PGLiteConnection` runs them one at a time, and other statements wait until one ends. PGlite transactions need `AsyncLocalStorage`, so they throw in a browser.

## Live rows

Loaded entities follow changes made by any client - an update settles in, a delete destroys, an insert changes nothing loaded.

```ts
import { PGlite } from '@electric-sql/pglite';
import { PGLiteConnection, Type, str } from '@expressive/postgres';

class Task extends Type {
  title = str();
}

const client = new PGlite();
await PGLiteConnection.new([Task], client);

const task = await Task.new({ title: "Draft" });

task.get(({ title }) => console.log(title));   // logs Draft, then Final

await client.query(`UPDATE task SET title = 'Final' WHERE id = $1`, [task.id]);
```

- Postgres 14+ (`CREATE OR REPLACE TRIGGER`).
- Each `sync` installs an `expressive_notify()` function and a trigger per table; tables created outside `sync` get theirs on the next one. Triggers `pg_notify` the `expressive_orm` channel with `{ table, op, id, row }`; `row` is dropped past 8000 bytes and the entity reloads it.
- `PGConnection` holds one pool client for `LISTEN`, from the first entity loaded until `close()`.
- A pooler in transaction mode (PgBouncer, some serverless proxies) drops notifications silently - connect directly or in session mode.
- Notifications carry the full row - any role that can `LISTEN` on the database receives it, whatever its table grants.
